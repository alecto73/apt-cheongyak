# 청약·미분양·대장아파트 지도

최근 3년 아파트 청약 결과, 준공후 미분양 단지, 지역별 대장아파트를
카카오맵 한 화면에서 함께 보는 웹앱입니다. PC와 휴대폰에서 같은 화면이
동작하고, 별도 앱 설치가 필요 없습니다.

지도를 확대하거나 지역을 누르면 전국 → 시·도 → 시·군·구 → 읍면동 순으로
경계가 바뀌며 들어갑니다. 누르지 않고 확대만 해도 가운데 지역으로 알아서
들어갑니다. 시·군·구에 닿으면 그 지역 단지가 점으로 찍히고 오른쪽에
상세가 나옵니다. 읍면동을 누르면 그 동에 든 단지만 남습니다.

세 가지를 겹쳐 보여주고 머리말의 토글로 각각 켜고 끕니다.

| 표시 | 뜻 |
|---|---|
| 파란·붉은·회색 동그라미 | 최근 3년 청약 공고 (마감 포함 / 전 타입 미달 / 결과 미공개) |
| 붉은 테 빈 동그라미 | 준공후 미분양 **추정** 단지 |
| 금색 마름모 | 대장아파트·최고가 단지 (빈 마름모는 대장후보) |

## 바로 보기

배포본: <https://alecto73.github.io/apt-cheongyak/>

손으로 띄울 때는 이렇게 합니다. 카카오맵은 등록된 도메인에서만 동작하므로
`localhost` 도 카카오 개발자 사이트의 플랫폼 > Web 에 넣어 두세요.

```
python3 -m http.server 8000 --directory web
# http://localhost:8000
```

파일을 그냥 더블클릭해서 여는 판본(`standalone.html`)은 없앴습니다.
`file://` 에서는 카카오맵이 뜨지 않기 때문입니다.

## 인증키

`.env` 파일에 넣습니다. 환경변수로 줘도 됩니다.

```
DATA_GO_KR_KEY=공공데이터포털 일반 인증키(Decoding)
KOSIS_KEY=KOSIS 공유서비스 인증키
```

공공데이터포털은 서비스별로 활용신청이 필요합니다. 위 표의 두 서비스를
각각 신청하세요. 개발단계는 자동승인이고 분양정보 서비스의 개발계정
트래픽은 일 40,000건입니다.

`requests` 로 `params=` 에 넘길 때는 Decoding 키, URL 문자열에 직접
붙일 때는 Encoding 키를 씁니다. 반대로 넣으면
`SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 납니다.

## 갱신

```
python3 etl.py              # 청약·미분양 전량 수집 후 집계
python3 geocode.py          # 새 공고의 좌표만 보충
python3 etl.py --offline    # 좌표를 반영해 재집계
python3 build_standalone.py
python3 build_map.py        # 시군구 경계 재생성 (행정구역이 바뀔 때만)
python3 build_emd.py        # 읍면동 경계 재생성 (build_map.py 뒤에)
python3 build_latlng.py     # 경계를 위경도로 변환 (앞 둘 중 하나라도 돌렸으면)
```

`etl.py` 한 번에 API 호출은 20회 미만입니다. 청약홈 API의 `perPage`
상한이 커서 공고별로 경쟁률을 따로 부르지 않고 전체 테이블을 통째로
페이징하기 때문입니다. 전량이 분양정보 2,868건 · 주택형 14,673건 ·
경쟁률 54,654건 규모라 증분 수집 없이 매일 새로 받는 편이 단순합니다.

미분양은 월말 기준으로 다음 달 말에 공표되므로 조회 시점과 1~2개월
차이가 납니다. 화면에 기준월을 항상 표시합니다.

권장 주기는 하루 한 번입니다.

```
0 5 * * * cd /srv/apt && python3 etl.py && python3 build_standalone.py
```

## 파일

```
regions.py            행정구역 정규화 규칙 (시도·시군구 별칭, 분할·병합)
slug.py               시도 이름 -> 파일명용 영문 슬러그
build_map.py          경계 병합·분할·단순화 -> web/map-national.json, web/map/*.json
build_emd.py          읍면동 경계 -> web/emd/*.json
geocode.py            우편번호·주소 -> 좌표 (web/geo-cache.json 에 캐시)
etl.py                API 수집 + 주소 정규화 + 집계 -> web/index.json, web/region/*.json
etl_daejang.py        실거래 수집 + 대장 판정 -> web/daejang/*.json
lawd.py               실거래 지역코드 -> 앱 시군구 대응표
daejang_seed.json     서울 미준공 대단지 조사값 (대장후보·세대수 보정)
build_latlng.py       SVG 경계 -> 위경도 폴리곤 (web/geo/*)
web/index.html        앱 본체 (카카오맵 SDK 외 의존성 없음)
```

데이터 파일명은 영문입니다(`web/map/gyeonggi.json`). 한글 파일명은
정적 호스팅에서 업로드 시 유니코드 정규화(NFC/NFD)가 바뀌어 브라우저
요청과 어긋나 404가 나는 일이 있습니다. 화면 표시는 한글 그대로입니다.

배포는 GitHub Pages 입니다. `main` 에 푸시되면
`.github/workflows/pages.yml` 이 `web/` 를 그대로 올립니다. 저장소
Settings > Pages > Source 가 `GitHub Actions` 여야 합니다.

브라우저에 나가는 키는 카카오 JavaScript 키 하나뿐입니다. 이 키는 등록된
도메인에서만 동작하므로 소스에 들어 있어도 됩니다. 수집용 인증키
(`DATA_GO_KR_KEY`, `KOSIS_KEY`)는 배치에서만 쓰여 노출되지 않습니다.

카카오 쪽 준비는 두 가지입니다. 앱의 **플랫폼 > Web > 사이트 도메인**에
`https://alecto73.github.io` 를 넣고, **제품 설정 > 카카오맵**을 켭니다.
키를 바꾸려면 `web/index.html` 의 `KAKAO_KEY` 한 줄만 고치면 됩니다.

첫 로딩은 `index.json` 18KB 와 `map-national.json` 47KB 입니다.
시·도를 고를 때 그 지역 경계(최대 36KB)와 공고 상세(경기도가 가장 큰
483KB)를 그때 받고, 시·군·구를 고를 때 그 시·도의 읍면동 경계(가장 큰
전남광주가 307KB)를 하나 더 받습니다. 전국을 합쳐 2.1MB 지만 한 번에
한 시·도만 받고 그 뒤로는 다시 받지 않습니다.
경계는 첫 화면에 시도 83KB, 시도를 고를 때 그 지역 시군구(최대 60KB),
시군구까지 들어갈 때 읍면동(최대 500KB)을 더 받습니다.

## 설계에서 판단이 필요했던 지점

**경계는 다시 내려받지 않고 투영을 거꾸로 풀었습니다.** 지도를 카카오맵으로
바꾸면서 위경도 폴리곤이 필요해졌는데, 기존 경계 파일은 화면 좌표로 투영된
SVG 경로입니다. `build_map.py` 의 변환이 선형이라 `build_latlng.py` 에서
정확히 역산할 수 있습니다. 덕분에 2026년 행정구역 개편 처리가 그대로
남았습니다. 전국 지도에는 투영 계수가 저장돼 있지 않아 같은 상수로 다시
계산하고, 결과가 파일의 viewBox 와 맞는지 먼저 확인한 뒤 진행합니다.

**준공후 미분양 단지는 추정입니다.** 전국 단지별 공식 자료가 없습니다.
KOSIS 는 시·군·구 집계만 주고, 단지 단위는 경기도·대구 같은 일부 지자체가
제각각 공개합니다. 그래서 세 조건을 모두 만족하는 청약 공고를 골라
표시합니다 — 입주예정월이 지났고, 청약에서 미달 타입이 있었고, 그
시·군·구의 준공후 미분양이 0호가 아닐 것. 세 번째가 헛다리를 크게 줄입니다.
통계상 한 채도 없는 지역이면 아무리 미달이었어도 지금은 팔렸다는 뜻이기
때문입니다. 현재 전국 145곳이 걸리고 그중 134곳에 좌표가 있습니다.
화면과 주석에 추정임을 명시합니다. 지자체 공개자료를 붙여 '확인된 단지'를
구분하는 것이 다음 숙제입니다.

**경계에 z 순서를 못박았습니다.** 시군구 위에 읍면동이 겹쳐 그려지는데
순서를 운에 맡기면 안쪽 경계를 눌러도 바깥 경계가 먼저 받습니다.
`FILL` 의 `zIndex` 로 시도 1, 시군구 2, 읍면동 3 을 고정했습니다.

**주소를 파싱해야 시군구가 나옵니다.** 청약홈 API의 지역 필드는
시도까지만 있습니다. 공급위치 주소가 자유 서술형이라 `Locator` 에
규칙을 겹쳐 쌓았습니다. 괄호 안 실주소 우선, 특례시 표기 제거,
폐지된 구 이름 승계, 시군구명 없이 동명만 있는 경우 단지명으로 재시도
순서입니다. 최근 3년 1,053건이 모두 매칭됩니다.

**집계 단위는 미분양 통계에 맞췄습니다.** 미분양은 경기도를 시 단위로만
제공하므로(수원시 장안구가 아니라 수원시) 지도 폴리곤도 특례시 일반구를
시로 병합했습니다. 결과가 16개 시도 230개 시군구로 KOSIS 목록과
정확히 일치합니다.

**2026년 행정구역 개편을 반영했습니다.** 7월 1일 전남광주통합특별시
출범으로 광주광역시와 전라남도가 폐지돼 시도가 16개입니다. 같은 날
인천이 개편돼 중구 내륙과 동구가 제물포구, 중구 영종도가 영종구,
서구가 아라뱃길 기준으로 검단구와 서해구로 갈렸습니다. 주소 표기가
개편 전후로 섞여 있어 양쪽을 모두 받습니다. 2018년 경계 원본에서
영종도는 별개 폴리곤이라 경도로 정확히 분리했고, 서구는 아라뱃길이
폴리곤 내부를 지나 위선으로 근사 절단했습니다. 이 절단선은 근사값이라
정밀한 경계가 필요하면 SGIS나 V-World의 현행 경계로 교체하세요.

대구경북통합특별시가 출범하면 `regions.py` 의 `SIDO_ORDER`, `SIDO_ALIAS`,
`GEO_SIDO` 만 고치면 됩니다.

**읍면동 경계는 투영을 다시 계산하지 않습니다.** `build_emd.py` 는
`web/map/*.json` 에 이미 들어 있는 `proj` 계수를 그대로 읽어 씁니다.
시군구 지도와 같은 좌표계로 만들어지므로 확대한 화면 위에 변환 없이
그대로 겹쳐집니다. 대신 `build_map.py` 를 다시 돌렸다면 `build_emd.py`
도 반드시 다시 돌려야 합니다. 시군구 경계 파일이 바뀌면 좌표계가
달라져 읍면동이 어긋납니다.

**읍면동은 행정동이고 주소는 법정동입니다.** 통계청 경계 자료가 주는
것은 행정동(사직동, 종로1·2·3·4가동)이고, 공고의 공급위치는 법정동으로
적힙니다. 그래서 동을 눌렀을 때 어느 공고가 그 안에 드는지는 이름이
아니라 좌표로 판정합니다. 브라우저의 `isPointInFill` 로 단지 점이 그
폴리곤 안에 있는지 직접 물어봅니다. 좌표가 없는 공고는 주소 문자열에서
동 이름을 찾아보고, 그것도 안 되면 목록에서 빠지며 몇 건인지 화면에
적습니다.

**2026년 개편 구는 폴리곤을 자르지 않았습니다.** 시군구 지도에서는
인천 서구를 위선으로 근사 절단했지만, 읍면동 단위에서는 각 동이 어느
쪽에 있는지로 나눕니다. 개편 경계가 동을 가르지 않으므로 절단보다
정확합니다. 검단구 4개 동, 영종구 4개 동으로 제대로 갈립니다.

**울릉군은 읍면동이 없습니다.** 경북 지도 뷰포트 밖이라 시군구 화면에
그려지지 않고, 확대할 상자도 없어 읍면동 층을 붙일 자리가 없습니다.
목록 버튼으로 고르면 청약·미분양 수치는 평소대로 나옵니다.

**경쟁률 해석.** 경쟁률 API는 순차 배정에서 마감된 지점에만 숫자가
들어가고 나머지 순위·지역은 `-` 입니다. 그래서 1순위 해당지역 →
1순위 기타경기 → 1순위 기타지역 → 2순위 순으로 훑어 처음 숫자가 나오는
칸을 마감 지점으로 봅니다. 끝까지 숫자가 없으면 미달입니다.

**분양가.** API가 주는 값은 주택형별 공급금액, 즉 해당 타입의 최고
분양금액(만원)입니다. 세대별 실제 분양가의 평균이 아니어서 화면에
'분양가'로 표기하고 주석에 명시했습니다. 평당가는 `SUPLY_AR`(공급면적)
기준으로 환산하고, 단지·지역 평균은 세대수 가중평균입니다.

## 대장아파트 보기

머리말의 **대장아파트** 탭을 누르면 같은 지도가 지역별 평균 매매 시세와
대장아파트 화면으로 바뀝니다. 시·도 → 시·군·구 순서는 같고, 서울은
법정동 단위 대장까지 보여줍니다. `index.html#daejang` 으로 열면 이
보기로 바로 시작합니다.

```
python3 etl_daejang.py             # 실거래 수집 + 대장 판정 + 좌표
python3 etl_daejang.py --offline   # raw/rtms 에 받아 둔 것으로 다시 집계
python3 build_standalone.py
```

`etl.py` 다음에 돌립니다. 대장후보의 84㎡ 분양가를 청약 공고에서 가져오기 때문입니다.

**활용신청이 더 필요합니다.** 같은 `DATA_GO_KR_KEY` 로 공공데이터포털에서
아래 네 서비스를 각각 신청하세요. 개발계정은 자동승인입니다.

| 서비스 | 쓰는 곳 |
|---|---|
| 국토교통부_아파트 매매 실거래가 상세 자료 | 시세·대장 판정 (필수) |
| 국토교통부_아파트 분양권전매 실거래가 자료 | 서울 대장후보 시세 |
| 국토교통부_공동주택 단지 목록제공 서비스 | 세대수 매칭 |
| 국토교통부_공동주택 기본 정보제공 서비스 | 세대수·사용승인일 |

K-apt 두 서비스가 없으면 세대수를 알 수 없어 거래량을 대단지 대용으로 쓰고
화면 하단에 그 사실을 적습니다. 카카오 REST 키를 `KAKAO_REST_KEY` 로 주면
단지 좌표를 카카오로 구하고, 없으면 Nominatim 을 씁니다.

**대장 판정.** 최근 12개월 매매 실거래(해제·직거래 제외)로 단지별 공급면적
평당 중위가를 냅니다. 최근 6개월 거래가 3건 이상이면 그 6개월만 씁니다.
연식·세대수 기준을 통과한 단지 중 평당가 1위가 대장입니다. 브랜드(10대
건설사 주력 브랜드)는 판정에 쓰지 않고 표시만 합니다.

**평당가는 공급면적 기준입니다.** 실거래 자료에는 전용면적만 있어 공급/전용
비율로 환산합니다. 청약 공고(`web/region`)에 같은 단지가 있으면 그 주택형의
실제 공급면적 비율을, 없으면 `SUPPLY_POINTS` 의 평형별 통상 비율(전용 59㎡≈25평,
84㎡≈34평, 114㎡≈44평)을 씁니다. 대장 카드에 어느 쪽으로 환산했는지 표시합니다.

| 지역 | 정규 기준 | 후보가 없을 때 완화 |
|---|---|---|
| 서울 구 | 10년·1,000세대 | 15년·1,000 → 15년·500 |
| 서울 법정동 | 10년·1,000세대 | 15년·1,000 → 10년·500 → 15년·500 → 20년·300 |
| 경기·인천·세종·광역시 | 10년·1,000세대 | 10년·700 → 15년·500 → 20년·300 |
| 그 밖의 지방 | 10년·500세대 | 15년·500 → 20년·300 |

기준은 `etl_daejang.py` 의 `tiers_for()` 한 곳에 있습니다. 법정동 단위를
경기·인천까지 넓히려면 `DONG_SIDO` 에 시도를 더하면 됩니다.

**대장후보(서울).** 아직 준공 전이거나 입주 석 달이 안 된 프리미엄 대단지는
`daejang_seed.json` 에 손으로 적어 둡니다. 세대수(조합원·임대 포함 전체),
입주 예정, 출처를 함께 둡니다. 청약홈 공급세대수는 일반분양분뿐이라 전체
세대수로 쓸 수 없기 때문입니다. 분양권·입주권 실거래가 있으면 시세를 붙이고
현 대장과 비교합니다. 시드에 없는 10대 브랜드 분양권 거래 단지는 참고로
따로 접어서 보여줍니다.

**코드 개편.** 2026-07-01 인천 개편과 전남광주 통합으로 실거래 지역코드가
바뀌어 옛 코드와 새 코드를 모두 조회하고 거래 단위로 중복을 지웁니다.
코드표는 `lawd.py` 에 있습니다.

**호출량.** 첫 실행은 시군구 코드 약 280개 × 13개월이라 3,700회 남짓입니다.
그 뒤로는 최근 3개월만 새로 받고 나머지는 `raw/rtms` 캐시(Actions 캐시)를
씁니다. K-apt 세대수는 `kapt-cache.json` 에 쌓여 다시 묻지 않습니다.

## 단지 위치 표시

청약홈 API는 좌표를 주지 않고 주소와 우편번호만 준다. 우편번호는
1,046건 전부에 채워져 있고 고유값이 829개뿐이라, 우편번호로 좌표를
구해 `web/geo-cache.json` 에 캐시한다. 한 번 구한 값은 다시 조회하지
않으므로 이후 갱신은 몇 초면 끝난다.

지오코딩은 인증키가 필요 없는 OpenStreetMap Nominatim 을 쓴다.
우편번호로 먼저 찾고, 실패하면 동까지 줄인 주소로 다시 찾는다.
현재 확보율은 공고 기준 89.4%다. 좌표를 못 찾은 공고는 지도에
찍히지 않고, 범례에 몇 건인지 표시한다.

**위치는 단지 정문이 아니라 그 우편번호 구역의 대표 지점이다.**
화면에도 '우편번호 기준 근사'로 표기했다. 더 정확한 좌표가 필요하면
`geocode.py` 의 `lookup()` 만 카카오 로컬 API나 브이월드 지오코더로
바꾸면 된다. 나머지 코드는 손댈 필요가 없다.

Nominatim 은 초당 1회 제한이 있어 캐시가 빈 상태에서 전체를 돌리면
20분쯤 걸린다. 이건 최초 1회뿐이다.

## 남은 개선거리

- 행정구역 경계를 현행 자료로 교체 (2018년 기준이라 그 뒤 신설·통합된
  행정동이 반영되지 않음, 인천 서구 절단선 정밀화)
- 미분양 시계열 추가 — KOSIS `newEstPrdCnt` 를 늘리면 추세선을 그릴 수 있습니다
- 오피스텔·민간임대 등 다른 주택 유형 (엔드포인트만 추가하면 됩니다)
- 시군구 검색창 — 지도를 두 번 누르지 않고 바로 이동
- 좌표 정확도 — 우편번호 구역 대표점 대신 단지별 실제 좌표
- 준공후 미분양 '확인' 레이어 — 경기도 오픈API, 대구 파일데이터 등
  지자체 공개 단지별 자료를 붙여 추정과 구분해 표시
- 대장아파트 좌표를 카카오로 구해 `daejang-geo.json` 에 저장하고 있는데,
  카카오 로컬 API 는 결과 저장을 허용하지 않습니다. Nominatim(ODbL) 으로
  되돌리거나 화면에서 실시간 변환하는 쪽으로 바꿔야 합니다

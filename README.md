# 시군구 청약·미분양 조회

특정 시·군·구의 최근 3년 아파트 청약 결과와 조회 시점 미분양 현황을
지도에서 두 단계로 찾아보는 웹앱입니다. PC와 휴대폰에서 같은 화면이
동작하고, 별도 앱 설치가 필요 없습니다.

전국 지도에서 시·도를 고르면 그 지역 시·군·구 지도가 열리고,
시·군·구를 고르면 지도가 그 지역으로 확대되면서 읍면동 경계가 얹히고
단지 위치가 점으로 찍히고, 오른쪽에 청약 공고가 연도별로 접힌 목록과
미분양 두 수치가 함께 나옵니다. 읍면동을 누르면 오른쪽 목록이 그 동의
공고만 남습니다. 점 색은 청약 결과(마감·미달·미공개)를 나타내고, 점을
누르면 해당 공고로 이동합니다. 지도는 미분양 세대수로 색을 채우고 청약 공고가 있는
지역에 작은 사각 마커를 얹어, 누르기 전에 어디를 봐야 할지 보이게
했습니다.

## 바로 보기

```
python3 -m http.server 8000 --directory web
# http://localhost:8000
```

서버를 띄우기 어려우면 `web/standalone.html` 을 브라우저로 바로
열면 됩니다. 데이터를 파일 안에 넣어둔 판본입니다. 브라우저는
`file://` 에서 데이터 요청을 막기 때문에 별도로 만들어 두었습니다.

## 인증키

`.env` 파일에 넣습니다. 환경변수로 줘도 됩니다.

```
DATA_GO_KR_KEY=공공데이터포털 일반 인증키(Decoding)
KOSIS_KEY=KOSIS 공유서비스 인증키
```

공공데이터포털은 서비스별로 활용신청이 필요합니다. 위 표의 두 서비스를
각각 신청하세요. 개발단계는 자동승인이고 분양정보 서비스의 개발계정
트래픽은 일 40,000건입니다.

`requests` 로 `params=` 에 넘길 때는 Decoding 키, URL 문자열에 직접
붙일 때는 Encoding 키를 씁니다. 반대로 넣으면
`SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 납니다.

## 갱신

```
python3 etl.py              # 청약·미분양 전량 수집 후 집계
python3 geocode.py          # 새 공고의 좌표만 보충
python3 etl.py --offline    # 좌표를 반영해 재집계
python3 build_standalone.py
python3 build_map.py        # 시군구 경계 재생성 (행정구역이 바뀔 때만)
python3 build_emd.py        # 읍면동 경계 재생성 (build_map.py 뒤에)
```

`etl.py` 한 번에 API 호출은 20회 미만입니다. 청약홈 API의 `perPage`
상한이 커서 공고별로 경쟁률을 따로 부르지 않고 전체 테이블을 통째로
페이징하기 때문입니다. 전량이 분양정보 2,868건 · 주택형 14,673건 ·
경쟁률 54,654건 규모라 증분 수집 없이 매일 새로 받는 편이 단순합니다.

미분양은 월말 기준으로 다음 달 말에 공표되므로 조회 시점과 1~2개월
차이가 납니다. 화면에 기준월을 항상 표시합니다.

권장 주기는 하루 한 번입니다.

```
0 5 * * * cd /srv/apt && python3 etl.py && python3 build_standalone.py
```

## 파일

```
regions.py            행정구역 정규화 규칙 (시도·시군구 별칭, 분할·병합)
slug.py               시도 이름 -> 파일명용 영문 슬러그
build_map.py          경계 병합·분할·단순화 -> web/map-national.json, web/map/*.json
build_emd.py          읍면동 경계 -> web/emd/*.json
geocode.py            우편번호·주소 -> 좌표 (web/geo-cache.json 에 캐시)
etl.py                API 수집 + 주소 정규화 + 집계 -> web/index.json, web/region/*.json
build_standalone.py   데이터를 끼워 넣은 단일 HTML 생성
web/index.html        앱 본체 (의존성 없음)
```

데이터 파일명은 영문입니다(`web/map/gyeonggi.json`). 한글 파일명은
정적 호스팅에서 업로드 시 유니코드 정규화(NFC/NFD)가 바뀌어 브라우저
요청과 어긋나 404가 나는 일이 있습니다. 화면 표시는 한글 그대로입니다.

배포는 `web/` 를 정적 호스팅에 올리면 끝입니다. 서버 코드가 없어
Cloudflare Pages, Netlify, S3 아무 곳이나 됩니다. 인증키는 배치에서만
쓰이므로 브라우저에 노출되지 않습니다.

첫 로딩은 `index.json` 18KB 와 `map-national.json` 47KB 입니다.
시·도를 고를 때 그 지역 경계(최대 36KB)와 공고 상세(경기도가 가장 큰
483KB)를 그때 받고, 시·군·구를 고를 때 그 시·도의 읍면동 경계(가장 큰
전남광주가 307KB)를 하나 더 받습니다. 전국을 합쳐 2.1MB 지만 한 번에
한 시·도만 받고 그 뒤로는 다시 받지 않습니다.
`standalone.html` 은 전부를 품고 있어 1.9MB 에서 4.0MB 로 커집니다.

## 설계에서 판단이 필요했던 지점

**주소를 파싱해야 시군구가 나옵니다.** 청약홈 API의 지역 필드는
시도까지만 있습니다. 공급위치 주소가 자유 서술형이라 `Locator` 에
규칙을 겹쳐 쌓았습니다. 괄호 안 실주소 우선, 특례시 표기 제거,
폐지된 구 이름 승계, 시군구명 없이 동명만 있는 경우 단지명으로 재시도
순서입니다. 최근 3년 1,053건이 모두 매칭됩니다.

**집계 단위는 미분양 통계에 맞췄습니다.** 미분양은 경기도를 시 단위로만
제공하므로(수원시 장안구가 아니라 수원시) 지도 폴리곤도 특례시 일반구를
시로 병합했습니다. 결과가 16개 시도 230개 시군구로 KOSIS 목록과
정확히 일치합니다.

**2026년 행정구역 개편을 반영했습니다.** 7월 1일 전남광주통합특별시
출범으로 광주광역시와 전라남도가 폐지돼 시도가 16개입니다. 같은 날
인천이 개편돼 중구 내륙과 동구가 제물포구, 중구 영종도가 영종구,
서구가 아라뱃길 기준으로 검단구와 서해구로 갈렸습니다. 주소 표기가
개편 전후로 섞여 있어 양쪽을 모두 받습니다. 2018년 경계 원본에서
영종도는 별개 폴리곤이라 경도로 정확히 분리했고, 서구는 아라뱃길이
폴리곤 내부를 지나 위선으로 근사 절단했습니다. 이 절단선은 근사값이라
정밀한 경계가 필요하면 SGIS나 V-World의 현행 경계로 교체하세요.

대구경북통합특별시가 출범하면 `regions.py` 의 `SIDO_ORDER`, `SIDO_ALIAS`,
`GEO_SIDO` 만 고치면 됩니다.

**읍면동 경계는 투영을 다시 계산하지 않습니다.** `build_emd.py` 는
`web/map/*.json` 에 이미 들어 있는 `proj` 계수를 그대로 읽어 씁니다.
시군구 지도와 같은 좌표계로 만들어지므로 확대한 화면 위에 변환 없이
그대로 겹쳐집니다. 대신 `build_map.py` 를 다시 돌렸다면 `build_emd.py`
도 반드시 다시 돌려야 합니다. 시군구 경계 파일이 바뀌면 좌표계가
달라져 읍면동이 어긋납니다.

**읍면동은 행정동이고 주소는 법정동입니다.** 통계청 경계 자료가 주는
것은 행정동(사직동, 종로1·2·3·4가동)이고, 공고의 공급위치는 법정동으로
적힙니다. 그래서 동을 눌렀을 때 어느 공고가 그 안에 드는지는 이름이
아니라 좌표로 판정합니다. 브라우저의 `isPointInFill` 로 단지 점이 그
폴리곤 안에 있는지 직접 물어봅니다. 좌표가 없는 공고는 주소 문자열에서
동 이름을 찾아보고, 그것도 안 되면 목록에서 빠지며 몇 건인지 화면에
적습니다.

**2026년 개편 구는 폴리곤을 자르지 않았습니다.** 시군구 지도에서는
인천 서구를 위선으로 근사 절단했지만, 읍면동 단위에서는 각 동이 어느
쪽에 있는지로 나눕니다. 개편 경계가 동을 가르지 않으므로 절단보다
정확합니다. 검단구 4개 동, 영종구 4개 동으로 제대로 갈립니다.

**울릉군은 읍면동이 없습니다.** 경북 지도 뷰포트 밖이라 시군구 화면에
그려지지 않고, 확대할 상자도 없어 읍면동 층을 붙일 자리가 없습니다.
목록 버튼으로 고르면 청약·미분양 수치는 평소대로 나옵니다.

**경쟁률 해석.** 경쟁률 API는 순차 배정에서 마감된 지점에만 숫자가
들어가고 나머지 순위·지역은 `-` 입니다. 그래서 1순위 해당지역 →
1순위 기타경기 → 1순위 기타지역 → 2순위 순으로 훑어 처음 숫자가 나오는
칸을 마감 지점으로 봅니다. 끝까지 숫자가 없으면 미달입니다.

**분양가.** API가 주는 값은 주택형별 공급금액, 즉 해당 타입의 최고
분양금액(만원)입니다. 세대별 실제 분양가의 평균이 아니어서 화면에
'분양가'로 표기하고 주석에 명시했습니다. 평당가는 `SUPLY_AR`(공급면적)
기준으로 환산하고, 단지·지역 평균은 세대수 가중평균입니다.

## 단지 위치 표시

청약홈 API는 좌표를 주지 않고 주소와 우편번호만 준다. 우편번호는
1,046건 전부에 채워져 있고 고유값이 829개뿐이라, 우편번호로 좌표를
구해 `web/geo-cache.json` 에 캐시한다. 한 번 구한 값은 다시 조회하지
않으므로 이후 갱신은 몇 초면 끝난다.

지오코딩은 인증키가 필요 없는 OpenStreetMap Nominatim 을 쓴다.
우편번호로 먼저 찾고, 실패하면 동까지 줄인 주소로 다시 찾는다.
현재 확보율은 공고 기준 89.4%다. 좌표를 못 찾은 공고는 지도에
찍히지 않고, 범례에 몇 건인지 표시한다.

**위치는 단지 정문이 아니라 그 우편번호 구역의 대표 지점이다.**
화면에도 '우편번호 기준 근사'로 표기했다. 더 정확한 좌표가 필요하면
`geocode.py` 의 `lookup()` 만 카카오 로컬 API나 브이월드 지오코더로
바꾸면 된다. 나머지 코드는 손댈 필요가 없다.

Nominatim 은 초당 1회 제한이 있어 캐시가 빈 상태에서 전체를 돌리면
20분쯤 걸린다. 이건 최초 1회뿐이다.

## 남은 개선거리

- 행정구역 경계를 현행 자료로 교체 (2018년 기준이라 그 뒤 신설·통합된
  행정동이 반영되지 않음, 인천 서구 절단선 정밀화)
- 미분양 시계열 추가 — KOSIS `newEstPrdCnt` 를 늘리면 추세선을 그릴 수 있습니다
- 오피스텔·민간임대 등 다른 주택 유형 (엔드포인트만 추가하면 됩니다)
- 시군구 검색창 — 지도를 두 번 누르지 않고 바로 이동
- 좌표 정확도 — 우편번호 구역 대표점 대신 단지별 실제 좌표
